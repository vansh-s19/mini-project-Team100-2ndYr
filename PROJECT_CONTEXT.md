## 1. Project Summary

**LandChain** is a decentralized real estate property registry and transfer platform built on Ethereum. It allows users to register properties by uploading government land documents, which are scanned via OCR, stored on IPFS, and recorded on the blockchain. A government authority can verify properties, and verified properties can be securely transferred between wallet addresses. The full ownership history is permanently tracked on-chain.

The project is **hackathon-ready** — it runs fully locally against a Hardhat test blockchain.

## 4. Smart Contract: `LandRegistry.sol`

**File:** `contracts/LandRegistry.sol` (270 lines, Solidity 0.8.19)

### Data Model
```solidity
struct Property {
    uint256 id;
    address owner;
    string registryId;
    string ipfsHash;
    bool verified;
    bool exists;
    uint256 timestamp;
    string ownerName;
    string plotNumber;
    string area;
    string propertyAddress;
}
```

### State Variables
- `address public governmentAuthority` — set at deployment (deployer address)
- `uint256 public propertyCount` — auto-incrementing property ID counter
- `mapping(uint256 => Property) public properties` — property data by ID
- `mapping(uint256 => address[]) public ownershipHistory` — owner history per property
- `mapping(address => uint256[]) public ownerProperties` — property IDs per owner

### Functions
| Function | Access | Description |
| -------- | ------ | ----------- |
| `registerProperty(registryId, ipfsHash, ownerName, plotNumber, area, propertyAddress)` | Anyone | Creates a new property. Caller becomes owner. `verified = false`. |
| `verifyProperty(propertyId)` | Authority only | Sets `verified = true`. |
| `rejectProperty(propertyId)` | Authority only | Sets `exists = false` (soft delete). |
| `transferProperty(propertyId, newOwner)` | Owner only | Transfers ownership. Property must be verified. Updates ownership history. |
| `getProperty(propertyId)` | View | Returns full Property struct. |
| `getOwnershipHistory(propertyId)` | View | Returns array of past owner addresses. |
| `getPropertiesByOwner(owner)` | View | Returns array of property IDs for a given address. |
| `getPropertyCount()` | View | Returns total registered property count. |

### Events
- `PropertyRegistered(propertyId, owner, registryId, ipfsHash, timestamp)`
- `PropertyVerified(propertyId, authority, timestamp)`
- `PropertyRejected(propertyId, authority, timestamp)`
- `PropertyTransferred(propertyId, previousOwner, newOwner, timestamp)`

### Modifiers
- `onlyAuthority` — restricts to `governmentAuthority`
- `onlyOwner(propertyId)` — restricts to current property owner
- `propertyExists(propertyId)` — requires `exists == true`

## 5. Backend API

**Entry point:** `backend/server.js` — Express server on port 5000.

**Middleware:** CORS (allows `localhost:3000`), JSON body parser, static file serving for `/uploads`.

### Endpoints

| Method | Path | Description |
| ------ | ---- | ----------- |
| `POST` | `/api/ocr/extract` | Accepts `multipart/form-data` with `document` field (image/PDF, max 10MB). Runs Tesseract OCR and returns parsed fields: `ownerName`, `plotNumber`, `registryId`, `area`, `address`, `date`. Also returns `rawText` and `confidence`. |
| `POST` | `/api/ipfs/upload` | Accepts `multipart/form-data` with `document` field (max 50MB). Uploads to Pinata if `PINATA_JWT` is set, otherwise generates a mock CID. Returns `cid`, `url`, `size`, `timestamp`. |
| `GET`  | `/api/health` | Health check. Returns OCR and IPFS service status. |

### OCR Field Extraction
The OCR route uses regex-based parsing (`parsePropertyFields()` in `backend/routes/ocr.js`) to extract:
- **Owner Name** — matches patterns like `Owner:`, `Name:`, `Shri/Mr./Mrs.`
- **Plot Number** — matches `Plot No`, `Khasra`, `Survey No`
- **Registry ID** — matches `Registry Id`, `Registration No`, `Deed No`
- **Area** — matches area values with units (sq ft, acres, hectares, bigha, etc.)
- **Address** — matches `Address:`, `Situated at:`, `Village:`, `District:`
- **Date** — matches multiple date formats (DD/MM/YYYY, DD-MM-YYYY, DD Month YYYY)

### IPFS Handling
- **With Pinata**: Uses Pinata's `pinFileToIPFS` API with JWT authentication. Stores file metadata (app name, upload timestamp).
- **Without Pinata (mock mode)**: Generates a random `Qm...`-prefixed mock CID for demo purposes. If Pinata upload fails, it automatically falls back to mock mode.

## 6. Frontend Architecture

**Framework:** Next.js 16 (App Router) + React 19 + TailwindCSS  
**Entry:** `new_frontend/LandChain-main/app/layout.tsx` → `page.tsx`

### Wallet Integration (`Web3Context.tsx`)
- Provides a React context wrapping MetaMask connection via `ethers.js v5`.
- Exposes: `account`, `provider`, `signer`, `contract`, `chainId`, `isConnecting`, `connectWallet()`, `disconnectWallet()`, `isConnected`.
- Listens for MetaMask events: `accountsChanged` (updates state), `chainChanged` (reloads page).
- Instantiates `ethers.Contract` using the ABI and address saved by the deploy script.

### Routes / Pages (App Router)
| Path | Component | Description |
| ---- | --------- | ----------- |
| `/` | `app/page.tsx` | Landing dashboard with modern 3D visualizations and features overview. |
| `/register` | `app/register/page.tsx` | Full registration flow: upload document → run OCR → review/edit extracted fields → upload to IPFS → call `registerProperty()` on contract |
| `/authority` | `app/authority/page.tsx` | Lists all pending (unverified) properties. Authority can verify or reject each. |
| `/properties` | `app/properties/page.tsx` | Shows properties owned by the currently connected wallet address. |
| `/transfer` | `app/transfer/page.tsx` | Allows the owner of a verified property to transfer it to a new wallet address. |
| `/verify` | `app/verify/page.tsx` | Public lookup page: enter a property ID to view its details, verification status, IPFS document link, and full ownership history timeline. |

### UI & Styling
- **Radix UI**: Accessible component primitives.
- **TailwindCSS**: Utility-first styling with a custom dark theme.
- **Framer Motion**: Smooth animations.
- Custom modern UI elements: `ElectricBorder`, `BorderGlow`.

## 7. Deployment Pipeline (`scripts/deploy.js`)

1. Gets the deployer signer from Hardhat.
2. Deploys `LandRegistry` contract, passing deployer address as the `authority`.
3. Waits for deployment confirmation.
4. **Automatically saves** the contract address to the backend and to `new_frontend/LandChain-main/lib/contract-address.json`.
5. **Automatically copies** the ABI to `new_frontend/LandChain-main/lib/LandRegistry.json`.
6. This means the frontend is always in sync with the latest deployment — no manual ABI copying needed.

## 8. How to Run the Project

**Prerequisites:** Node.js 18+, MetaMask browser extension.

Open 3 terminals in the project root:

```bash
# Terminal 1 — Local Blockchain (keep running)
npm run node

# Terminal 2 — Compile, Deploy, then Start Backend
npm run compile
npm run deploy
npm run backend

# Terminal 3 — Frontend Dev Server
npm run frontend
```

**MetaMask Setup:**
1. Add network: Hardhat Local → RPC `http://127.0.0.1:8545`, Chain ID `31337`
2. Import a test account using a private key from the `npm run node` terminal output
3. The deployer (Account #0) is also the government authority

**Frontend URL:** `http://localhost:3000`  
**Backend URL:** `http://localhost:5000`  
**Blockchain RPC:** `http://127.0.0.1:8545`

## 10. Key Design Decisions

1. **Mock IPFS mode:** If `PINATA_JWT` is not set in `backend/.env`, IPFS uploads generate a fake CID. This allows the entire demo to work without any external API keys.
2. **Authority = Deployer:** The address that deploys the contract is automatically set as the `governmentAuthority`. In a real system, this would be a multisig or DAO.
3. **ethers.js v5 (not v6):** The frontend uses ethers v5 (`new ethers.providers.Web3Provider`), not v6 syntax. This is intentional for MetaMask compatibility.
4. **ABI auto-sync:** The deploy script writes `contract-address.json` and `LandRegistry.json` directly into `new_frontend/LandChain-main/lib/`, so the frontend never has a stale ABI.
5. **Soft delete for rejection:** `rejectProperty()` sets `exists = false` rather than deleting storage, preserving gas efficiency and event history.
6. **OCR is regex-based:** The `parsePropertyFields()` function uses multiple regex patterns to extract structured fields from raw OCR text. It handles partial extraction gracefully — any fields it can't identify are returned as empty strings, and the frontend allows manual correction.
